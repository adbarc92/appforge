## Adaptations made vs. the plan

The plan as written had four points of drift from the actual codebase. They were resolved in the commits above; capturing them here so a future session doesn't redo the analysis:

1. **Registry API** — plan called `registry.get(name, mock=...)`. Actual API is `registry.get_agent(name)`. Mock-mode is driven by `Config.mock_agents` and the registry's import-failure fallback.
2. **`AgentResult` shape** — plan called `result.get("status")` / `result["artifact"]`. `AgentResult` is a dataclass, so the orchestrator uses an `_result_field` helper that handles both dict and dataclass results. The new `ClarifyingPmAgent` mock subclass returns plain dicts.
3. **First-event assertion** — plan's test asserted the first `agent_status` event has `agent == "clarifying_pm"`, but the orchestrator emits an `orchestrator` running event first. Test was changed to filter for clarifying_pm.
4. **`Question` lookup** — plan used a convoluted `type(state).model_fields["questions"].annotation.__args__[0]` reflection. Replaced with a direct `from backend.graph import Question`.

## Two real bugs caught during smoke

Both worth knowing about because they shaped the fix in `5a9a0b7`:

1. **`compile(interrupt_before=...)` without a checkpointer is a hard stop.** LangGraph returns from `ainvoke` at the interrupt point — `approval_node` never runs, the user's resume value has no destination, and the mock keeps re-emitting question #1. `backend/graph.py` now skips `interrupt_before` unless a checkpointer is provided. Slice 5 re-adds it with `SqliteSaver`.
2. **`approval_node` was reading `decision.get("decision", ...)`, but `user_message` resumes with `{"answer": text}`.** Until a PRD exists, treat the resume value as an answer to the latest question: append to `state.answers`, route back to `clarifying_pm` via `approval_status="rejected"`. Once `state.prd` is set, treat input as the approval decision (any non-empty input approves in mock mode). `clarifying_node` now also emits `approval_required` with the PRD content so `PRDViewer` renders.

## Known limitation: page reload resets the project UI

Reloading the browser drops Zustand state, and the backend currently has no checkpointer to hydrate from. The empty `load_project` handler is the placeholder for **Slice 5**, which introduces:

- `SqliteSaver` checkpointing on every node transition
- `load_project` reading the latest checkpoint and emitting `project_state`
- Frontend hydration via the existing `ProjectStateSnapshot` path (`useSocket.ts` already wires `socket.on("project_state", onProjectState)`)

If reload-recovery becomes painful during Slice 4 development, we can layer a localStorage shim for the visible transcript without touching the backend, but that's a workaround — Slice 5 is the real fix.
